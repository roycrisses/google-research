## 2025-05-22 - ROUGE LCS Algorithmic Optimizations
**Learning:** The default ROUGE LCS implementation suffered from several performance anti-patterns in Python: O(M*N) memory usage for simple length checks, O(N^2) list building using `insert(0, ...)`, and redundant O(M*N) DP calculations for disjoint token sequences or non-overlapping sentences in summaries.
**Action:** Always use space-optimized DP ($O(\min(M, N))$) when only the length is needed. Use `append()` + `reverse()` for efficient list building. Implement fast-path checks using `set` intersections to bypass expensive algorithms. Pre-calculate sets in loops to avoid redundant conversions. Use local variable lookups and conditional expressions instead of `max()` in tight loops.

## 2025-05-23 - Set-Based Fast-Paths in LCS Table & Length, and Zip-Based Ngrams
**Learning:** Checking set membership of the current token in the candidate token set before executing the inner DP loop of LCS reduces mismatching token steps from $O(N)$ to $O(1)$. In `_lcs_table`, this allows reusing the previous row's list reference directly, saving $O(N)$ allocations. In `_lcs_length`, it allows using a fast slice-copy `curr_row[:] = prev_row`. Additionally, generator expressions in `_create_ngrams` incur significant overhead compared to Python's C-optimized `zip` with slicing.
**Action:** When working with 2D dynamic programming matrices, identify row-invariance conditions (like character mismatch) and skip/reassign whole rows using fast-path set checks. Use `collections.Counter(six.moves.zip(*[tokens[i:] for i in range(n)]))` for highly efficient n-gram generation.
