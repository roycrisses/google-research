## 2025-05-22 - ROUGE LCS Algorithmic Optimizations
**Learning:** The default ROUGE LCS implementation suffered from several performance anti-patterns in Python: O(M*N) memory usage for simple length checks, O(N^2) list building using `insert(0, ...)`, and redundant O(M*N) DP calculations for disjoint token sequences or non-overlapping sentences in summaries.
**Action:** Always use space-optimized DP ($O(\min(M, N))$) when only the length is needed. Use `append()` + `reverse()` for efficient list building. Implement fast-path checks using `set` intersections to bypass expensive algorithms. Pre-calculate sets in loops to avoid redundant conversions. Use local variable lookups and conditional expressions instead of `max()` in tight loops.

## 2025-08-04 - JAX Sinkhorn Dual Updates Factorization
**Learning:** In 1D Optimal Transport, computing the softmin over intermediate `center` coordinates (where `center = cost - f - g`) inside the inner Sinkhorn loop creates expensive $O(N^2)$ memory allocations and operations. Since the dual variables `f` or `g` are constant along the axis of reduction, they can be pulled out of the exponent in the `logsumexp` formulation. This simplifies updates to a direct form (e.g., `g = eps * logb - eps * logsumexp((f - cost) / eps, axis=1)`) that avoids 3D tensor allocations and softmin call overheads.
**Action:** In iterative exponential/logspace algorithms like Sinkhorn, always factor out terms constant along the reduction axis to simplify formulas and eliminate intermediate high-dimensional array allocations. Precompute division constants (e.g., `inv_eps = 1.0 / eps`) to replace element-wise divisions with multiplications.
