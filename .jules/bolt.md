## 2025-05-22 - ROUGE LCS Algorithmic Optimizations
**Learning:** The default ROUGE LCS implementation suffered from several performance anti-patterns in Python: O(M*N) memory usage for simple length checks, O(N^2) list building using `insert(0, ...)`, and redundant O(M*N) DP calculations for disjoint token sequences or non-overlapping sentences in summaries.
**Action:** Always use space-optimized DP ($O(\min(M, N))$) when only the length is needed. Use `append()` + `reverse()` for efficient list building. Implement fast-path checks using `set` intersections to bypass expensive algorithms. Pre-calculate sets in loops to avoid redundant conversions. Use local variable lookups and conditional expressions instead of `max()` in tight loops.

## 2025-05-23 - Instruction Following Evaluation Regex & Pre-computation Optimizations
**Learning:** Recompiling regular expressions on every `check_following` invocation (especially when checking candidates in `test_instruction_following_loose`) and re-tokenizing static reference text (like `original_paragraph` in `RephraseParagraph`) creates significant CPU overhead in evaluation loops.
**Action:** Always pre-compile instance-level regular expressions during `build_description()` / `__init__()`. Pre-calculate frequency counters (`collections.Counter`) for reference texts upon construction. Use fast-path character counts (`sum(1 for c in value if c.isupper())`) or substring filters (`[s for s in key_sentences if s in value]`) to skip expensive NLTK tokenization or sentence splitting when the necessary conditions cannot be met.
